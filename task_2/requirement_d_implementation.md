# Requirement D - NLP System Implementation

The implementation begins with the 1,000-row processed restaurant-review dataset created in Task 1 and copied to `task_2/data/restaurant_reviews_processed.csv`. The dataset contains 500 positive and 500 negative reviews. Python and pandas load the file into a DataFrame, then `validate_dataset()` checks the required columns, row count, class counts, missing `cleaned_review` and `sentiment` values, and the permitted labels before training. These checks explicitly stop the workflow with a clear error if the expected modeling data are unavailable or structurally invalid. The system selects `cleaned_review` as the input feature and `sentiment` as the binary target. Next, `train_test_split()` creates an 80/20 split with `random_state=42` and `stratify=target`, producing a repeatable partition while preserving the class balance between training and testing data. Beginning with already processed text makes preprocessing an explicit part of the system design; recent survey evidence indicates that preprocessing choices should be considered in relation to the classifier and dataset used (Siino et al., 2024).

The core NLP workflow is implemented with scikit-learn. `build_baseline_model()` constructs a `Pipeline` containing `TfidfVectorizer(lowercase=False)` followed by `LogisticRegression(max_iter=1000, random_state=42)`. TF-IDF converts each processed review into numerical term-weight features; it is not a neural embedding. Because the split occurs before `model.fit()`, the pipeline learns the TF-IDF vocabulary and inverse-document-frequency values from training reviews rather than from the full dataset, then supplies those vectors to the binary Logistic Regression classifier. This keeps feature transformation and classification in one reproducible training workflow and avoids exposing test-partition text to TF-IDF fitting before later evaluation. The fitted model generates predictions for short cleaned-style sample phrases to demonstrate functioning inference, without reporting formal performance measures. Its configured classifier has a maximum of 1,000 training iterations and uses the same fixed random state as the split. The use of a transparent classical baseline is consistent with recent sentiment-analysis research that compares traditional machine-learning approaches alongside more complex alternatives, while leaving this project's model-specific evaluation for a later stage (Srianan et al., 2025).

Python provides the implementation runtime, while Visual Studio Code is used to edit `main.py`, inspect the project structure, and access the terminal. PowerShell runs the application and Git commands, enabling the dataset validation and model-training workflow to be executed from the repository root. The code is organized into focused functions for loading, validation, splitting, model construction, training, prediction demonstration, and summary reporting, which makes the workflow easier to inspect and repeat. Git records the implementation in separate commits for the setup, working model, libraries-and-tools documentation, and this implementation description; GitLab stores the pushed `working-branch` and its history. This branch-based history identifies when each required implementation artifact was introduced and allows the current version to be compared with prior commits. Together with the fixed random state and modular code, these tools provide a traceable, maintainable path from the processed dataset to a trained baseline pipeline without claiming unperformed evaluation or optimization work.
